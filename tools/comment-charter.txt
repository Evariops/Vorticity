# usage: edit the patterns here, not in the test that reads them.
#
# One entry per line. Blank lines and lines opening with a hash are ignored. Every entry is a
# regular expression, matched case-sensitively unless it says otherwise.
#
# Sections:
#   acronyms  a capitalised run that is a name or an identifier rather than emphasis. Matched as a
#             whole word, and subtracted from the finding-identifier pattern too, so that a type
#             like I128 is not read as a finding called I-128.
#   reference a pointer to something outside the file: a document, a section, an audit entry, a
#             date, a commit.
#   history   a trace of how the code got here, as opposed to what it does.

[IUF][0-9]{1,3}

[reference]
\.md\b
# A vendored specification file. The word boundary keeps a namespace such as google.protobuf out.
\.(fbs|proto|toml)\b
§
\bdocs/[0-9]
\b(PERF|BENCH|WRITE|IMPL|AUDIT)-[A-Za-z]
# A finding or plan identifier: one or two capitals, an optional dash, up to three digits.
\b[A-Z]{1,2}-?[0-9]{1,3}[a-z]?\b
# A date, to the month.
\b20[0-9]{2}-[0-9]{2}
# An abbreviated commit hash.
\b[0-9a-f]{7,}\b
